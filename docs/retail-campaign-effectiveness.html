Background

Retailers often invest in direct-marketing campaigns, such as coupons. The business question is simple: do these campaigns actually change what households buy?

Question for this project: Did these campaigns increase household spend, and did all household types respond in the same way?

This first part of the project explains the data, checks its quality and describes how households shop. Later parts will measure the effect of the campaigns themselves.

About the data

The data covers two years of grocery shopping by 2500 households who shop regularly at one U.S. retailer. It records every product they bought, as well as which households were targeted by 30 direct-marketing campaigns and which coupons were redeemed.

Key terms

  • Household: one shopping household, identified by a household key.
  • Basket: one shopping trip. All line items bought together share the same basket ID.
  • Line item: one product on one receipt. Each row of the transactions table is a line item.

Sales and quantity values

Checks for zero or negative sales and zero quantities, which can distort spend totals..

Show code

sales_quantity_values <- transactions %>%

    min_sales              = min(sales_value),
    max_sales              = max(sales_value)

Sales and quantity values
Column Values
zero_sales 18850
negative_value_sales 0
zero_quantity 14466

There are no negative sales values, so no returns or refunds are recorded as negative sales. However, 18,850 lines (0.73% of all lines) have a sales value of zero, and 14,466 lines (0.56%) have a quantity of zero.

What this means for the analysis:

  • Spend: Lines with zero sales add nothing to a household’s total spend, so they don’t distort spend totals.
  • Averages per line: They do pull the average line value down slightly, because they count as lines. Household and basket totals are not affected.
  • Units: A quantity of zero can’t be used to work out a price per unit, because dividing by zero gives an error. Quantity is not used for that in this report.
  • Scale: Both groups are under 1% of the data, so the main results are very unlikely to change. These rows are kept in, and flagged here for transparency.

weekly_sales <- transactions %>%

## Sales and quantity values
Checks for zero or negative sales and zero quantities, which can distort spend totals..

```{r}
# Sales and quantity values
sales_quantity_values <- transactions %>% 
  summarise(
    zero_sales             = sum(sales_value == 0),
    negative_value_sales   = sum(sales_value < 0),
    zero_quantity          = sum(quantity == 0),
    min_sales              = min(sales_value),
    max_sales              = max(sales_value)
  )

# Turn the wide row into a long table, one row per column
sales_quantity_values_wide <- sales_quantity_values %>%
  pivot_longer(
    cols      = everything(),
    names_to  = "Column",
    values_to = "Values"
  )

# Display in kable
sales_quantity_values_wide %>%
  kable(caption = "Sales and quantity values") %>%
  style_table() 
```

There are no negative sales values, so no returns or refunds are recorded as negative sales.
However, **`r big(sales_quantity_values$zero_sales)`** lines
(`r scales::percent(sales_quantity_values$zero_sales / nrow(transactions), accuracy = 0.01)`
of all lines) have a sales value of zero, and **`r big(sales_quantity_values$zero_quantity)`**
lines (`r scales::percent(sales_quantity_values$zero_quantity / nrow(transactions), accuracy = 0.01)`)
have a quantity of zero.

**What this means for the analysis:**

-   **Spend:** Lines with zero sales add nothing to a household's total spend, so they don't distort spend totals.
-   **Averages per line:** They do pull the average line value down slightly, because they count as lines. Household and basket totals are not affected.
-   **Units:** A quantity of zero can't be used to work out a price per unit, because dividing by zero gives an error. Quantity is not used for that in this report.
-   **Scale:** Both groups are under 1% of the data, so the main results are very unlikely to change. These rows are kept in, and flagged here for transparency.

## Weekly sales over time

```{r weekly-sales-line}

weekly_sales <- transactions %>%
```
